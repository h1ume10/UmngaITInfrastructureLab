# Evidence captions: 04 Departmental file server

All 16 files are in this folder. Each was checked for passwords, licence keys, credential boxes, tenant names, employer data and MAC addresses, and none was found.

Thirteen captures are headline evidence and three are supporting (the Server Manager pool view, the PowerShell window with the spelling error, and the File Explorer drive view).

1. 04_step01_disk_management_svr1.png: Disk Management on UMNGA-SVR1, taken on 7 November 2026. Disk 0 is Basic, 60.00 GB, Online, with a 100 MB NTFS system partition, C: at 59.13 GB NTFS and a 786 MB recovery partition. C: shows 42.62 GB free. The CD drive D: holds the VirtualBox Guest Additions. The title bar shows the snapshot "Stage 3 before RDS", because no Stage 4 snapshot existed yet. The screenshot does not show the partition style. The MBR style of Disk 0 appears in capture 2.
2. 04_step02_physicaldisks_before_pool_svr1.png: PowerShell on SVR1. Get-PhysicalDisk lists DeviceId 0 (64424509440 bytes, CanPool False, Insufficient Capacity) and DeviceId 1, 2 and 3 (5368709120 bytes each, CanPool True, all OK). Get-Disk lists disk 0 as MBR and disks 1, 2 and 3 as RAW, all Online. The title bar shows the snapshot "Stage 4 before pool".
3. 04_step02_pool_powershell_svr1.png: PowerShell on SVR1 after the pool existed. Get-PhysicalDisk shows all four disks with CanPool False. The UniqueId column reads ATAVBOX HARDDISK for each one. Get-PhysicalDisk -StoragePool for Umnga Pool lists DeviceId 1, 3 and 2, each 5368709120 bytes. It does not show the New-StoragePool command.
4. 04_step02_storage_pool_svr1.png (supporting): Server Manager, File and Storage Services, Storage Pools. Umnga Pool is listed as a Storage Pool under Windows Storage, with capacity 13.5 GB and 12.7 GB free. The physical disks panel lists only one row, VBOX HARDDISK, 5.00 GB, although the pool holds three disks. The virtual disks panel was still empty at this point.
5. 04_step02_virtual_disk_svr1.png: PowerShell on SVR1. The command New-VirtualDisk with the pool Umnga Pool, the name Departments, Mirror, 5GB and Thin returns Departments, Mirror, FaultDomainRedundancy 1, OK, Healthy, Size 5 GB and FootprintOnPool 1 GB. Get-VirtualDisk then shows Mirror, Thin, 5368709120, OK and Healthy. The title bar shows the snapshot "Stage 4 pool built".
6. 04_step02_volume_powershell_svr1.png (supporting): PowerShell on SVR1. Get-Disk for the Departments virtual disk shows Number 4, RAW, Offline, IsOffline True. The first formatting attempt fails with the red error that the term Initialise-Disk is not recognised. The second attempt, with Initialize-Disk, completes and shows drive E, Departments, NTFS, Fixed, Healthy, OK, 4.96 GB remaining of 4.98 GB.
7. 04_step02_volume_svr1.png: PowerShell on SVR1. A first Get-Disk with a mistyped property name shows Number 4, Departments, 5368709120 and Online with the partition style missing. Get-Volume for drive E shows Departments, NTFS, Healthy, 5325115392 free of 5350879232. The corrected Get-Disk shows GPT, Online and IsOffline False. The title bar shows the snapshot "Stage 4 volume built".
8. 04_step02_departments_drive_svr1.png (supporting): File Explorer, This PC. Local Disk (C:) shows 42.5 GB free of 59.1 GB, the CD drive (D:) is VirtualBox Guest Additions, and Departments (E:) shows 4.95 GB free of 4.98 GB.
9. 04_step03_file_server_role_svr1.png: the Add Roles and Features Wizard, Installation progress, Results. It reads "Installation succeeded on UMNGA-SVR1.umnga.local" and lists File and Storage Services, File and iSCSI Services and File Server. No restart message is shown. The title bar shows the snapshot "Stage 4 before file server".
10. 04_step04_department_folders_svr1.png: File Explorer on Departments (E:) listing seven folders: MunicipalManagerOffice, Finance, CorporateServices, CommunityServices, TechnicalServices, PlanningEconomicDev and ICT. The status bar reads 7 items. The title bar shows the snapshot "Stage 4 before shares".
11. 04_step04_share_finance_svr1.png: Server Manager, Shares. UMNGA-SVR1 (1) lists the share Finance with local path E:\Finance, protocol SMB and availability type Not Clustered. The volume pane shows Departments (E:), capacity 4.98 GB, 0.5% used, 24.6 MB used and 4.96 GB free. The quota pane says File Server Resource Manager must be installed.
12. 04_step04_ntfs_finance_svr1.png: Advanced Security Settings for E:\Finance, Permissions tab. The entries are Administrators, SYSTEM and CREATOR OWNER with Full control (CREATOR OWNER on subfolders and files only), and GG_Finance (UMNGA\GG_Finance) with Modify on this folder, subfolders and files. Every entry is inherited from None, and the Enable inheritance button is offered. The title bar shows the snapshot "Stage 4 before NTFS".
13. 04_step04_effective_access_allowed_svr1.png: the Effective Access tab for E:\Finance. Full control, Delete subfolders and files, Change permissions and Take ownership are crossed out, and the other ten items are ticked, which is the Modify level. The user line is scrolled out of view and a taskbar pop up covers part of the list, so the screenshot does not show which account was tested. My notes say it was ndlovut, a Finance user.
14. 04_step04_effective_access_blocked_svr1.png: the Effective Access tab for E:\Finance. Every one of the fourteen items is crossed out, with Access limited by File Permissions. The user line is not visible and a taskbar pop up covers part of the right hand column. My notes say it was pillayz, a Planning user.
15. 04_step04_all_shares_svr1.png: PowerShell on SVR1. The tail of the loop and the six New-SmbShare results with ScopeName * are visible. Get-SmbShare for paths under E:\ lists CommunityServices, CorporateServices, E$ (path E:\, Unrestricted), Finance, ICT, MunicipalManagerOffice, PlanningEconomicDev and TechnicalServices, all AccessBased except E$. The title bar shows the snapshot "Stage 4 before script".
16. 04_step04_all_acls_svr1.png: PowerShell on SVR1. A listing of the access entries on each folder on E: shows, for all seven, CREATOR OWNER, NT AUTHORITY\SYSTEM, BUILTIN\Administrators and the folder's own UMNGA\GG_ group.
